Eine Website ohne Build-Schritt

Warum diese Seite aus reinem HTML, CSS und JavaScript besteht, und wo das an Grenzen stößt.

Entwurf5 min LesezeitWebArchitektur
Skizze · Dieser Artikel ist ein Entwurf, um Layout und Ton der Notizen zu zeigen.

Diese Seite besteht aus statischen Dateien: HTML, ein gemeinsames Stylesheet und etwas JavaScript pro Mini-App. Es gibt kein Framework, keinen Bundler und keinen Server-Code. GitHub Pages liefert das Repository direkt aus, jeder Merge auf main ist sofort online.

Was dafür spricht

  • Jede Datei im Repository ist genau das, was der Browser lädt. Fehler lassen sich ohne Source Maps finden.
  • Keine Abhängigkeiten, die veralten. three.js liegt fest versioniert unter vendor/.
  • Eine Mini-App ist ein Ordner mit index.html, app.css und app.js.

Wo es hakt

Ohne Build-Schritt gibt es kein Cache-Busting über Dateinamen. Ändert sich HTML, das neue CSS-Klassen braucht, hänge ich eine Version an:

<link rel="stylesheet" href="style.css?v=4">

Kopfzeile und Fußzeile stehen in jeder Datei einzeln. Für ein paar Seiten ist das in Ordnung, für einen Blog mit vielen Artikeln nicht mehr.

Der nächste Schritt

Für die Notizen plane ich einen Static-Site-Generator, der Markdown in HTML umwandelt und nur in GitHub Actions läuft. Im Repository bleibt Quelltext, ausgeliefert wird weiterhin statisches HTML.
